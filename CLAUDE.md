# Глобальные правила Claude Code

Личный харнес Кирилла Розова: Android/KMP, iOS/SwiftUI, плюс сопровождение самого этого конфига. Здесь только то, что нужно в любой сессии. Остальное грузится по месту — стековые правила по `paths:`, рабочие процессы скиллами.

## Нельзя нарушать

- **Не обходить git hooks** (`--no-verify`, `--no-gpg-sign` и т.п.) без явной просьбы. Hook упал — устранить причину.
- **Не коммитить и не пушить в main/master/develop.**
- **Force push только `--force-with-lease` или `--force-if-includes`.**

Это же закрыто хуками и deny-правилами — здесь перечислено, чтобы не тратить ход на отклонённую попытку.

## Принципы

- **Минимальный diff.** При целевом изменении трогать только то, что требует задача: не переименовывать переменные, не добавлять валидацию, не реструктурировать «для ясности», не модернизировать паттерны без просьбы. Структурные улучшения — отдельным коммитом с согласия. Зелёные тесты раздутый diff не оправдывают: избыточное редактирование невидимо для тестов и видно каждому ревьюеру.
- **Эмпирическая проверка вместо кабинетного вывода.** Прежде чем объявить путь нереализуемым или реализуемым на основе расчёта — запустить минимальный тест, который это разрешит. Вердикт остаётся гипотезой, пока реальный запуск её не подтвердил. Явно помечать, что теория, а что проверено. Исполнитель таких проверок — агент `spike-runner`.
- **Возражать, а не соглашаться по умолчанию.** Выбор ведёт к workaround, дыре в безопасности или техдолгу — сказать и предложить альтернативу. Это относится и к правилам здесь. Пользователь настаивает после возражения — обозначить риск и выполнить, к тому же возражению не возвращаться.
- Изменение обязано затронуть другие файлы — обновить их без вопросов; возможно затрагивает — сказать с конкретикой.

## Синхронизация ~/.claude

Публичный репозиторий `kirich1409/claude-global-settings`, модель **PR-only**: `main` чистая, любая правка tracked-файла идёт через ветку и PR. `csync` и SessionStart auto-pull только тянут, никогда не коммитят. Полное правило — [[claude-repo-pr-workflow]].

## Правила

Всегда активны — их содержимое ниже по контексту, пересказывать здесь нечего:
**ast-index.md**, **communication.md**, **git-workflow.md**, **model-effort-routing.md**, **orchestration.md**, **task-execution.md**.

Загружаются по `paths:` при работе с соответствующими файлами — содержание смотреть в самом правиле:

- исходники: **code-policies.md**, **code-style.md**, **logging.md**, **testing-gate.md**
- `**/*.kt`, `**/*.kts`: **kotlin-style.md**, **coroutines.md**, **compose-style.md**
- `**/*.swift`: **swift-concurrency.md**, **swift-testing.md**, **swiftui-state.md**, **swiftui-patterns.md**, **swiftui-performance.md**, **swiftui-design-system.md**
- Gradle-файлы: **gradle-style.md**
- Android/KMP: **android-cli.md**
- tracked-файлы `~/.claude`: **claude-repo-pr-workflow.md**

## Скиллы для рабочих процессов

Грузятся по смыслу задачи, а не постоянно. Ключевые: `verification` (как доказывать корректность — пирамида L0–L5, источники истины, гейты), `research-sources` (внешние источники, tiers T1–T4, верификация API), `long-task-state` (состояние длинной задачи в `swarm-report/`), `evaluate-dependency` (гейт добавления зависимости), `drive-to-merge` (PR до мержа, доска, auto-merge). Полный список — `/find-skills` или каталог в контексте сессии.

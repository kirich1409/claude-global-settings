# Глобальные правила Claude Code

## Нельзя нарушать

- **Не обходить git hooks** (`--no-verify`, `--no-gpg-sign`, `-c commit.gpgsign=false`) без явной
  просьбы пользователя. Hook упал — устранить причину.
- **Force push только `--force-with-lease` или `--force-if-includes`.** Обычный `--force` запрещён.

## Делегирование

Порог, а не запрет по типу файла: главная сессия делает сама то, что закрывается несколькими
вызовами инструментов, и делегирует крупное, самостоятельное и параллелизуемое. Полная граница —
[[orchestration]].

## Модель доставки

**Задаёт репозиторий, а не харнес.** Нужен ли PR и закрыта ли `main` для прямых коммитов — решают
branch protection репозитория и инструкции проекта. Конвенции веток и коммитов — [[git-workflow]],
это дефолты, а не запреты.

`~/.claude` — публичный репозиторий `kirich1409/claude-global-settings`; правки идут прямо в `main`,
доставляет их `csync`. Полное правило — [[claude-repo-sync]].

## Принципы

- **Минимальный diff.** Трогать только то, что требует задача: не переименовывать переменные, не
  добавлять валидацию, не реструктурировать «для ясности», не модернизировать паттерны без просьбы.
  Структурные улучшения — отдельным коммитом с согласия. Зелёные тесты раздутый diff не оправдывают.
- **Эмпирическая проверка вместо кабинетного вывода.** Не объявлять путь реализуемым или
  нереализуемым по расчёту — запустить минимальный различающий тест. Вердикт остаётся гипотезой,
  пока реальный запуск её не подтвердил. Помечать, что теория, а что проверено.
- **Артефакт агента неверен, пока минимальный верификатор не доказал обратное.** Конфиг →
  `validate-config`, schema, dry-run; hook → реальный запуск; permission-правила → warnings свежей
  сессии. «Валидный JSON» и «выглядит правильно» проверкой не являются. Исключения gates снимают
  церемонию `/finalize` и `/acceptance`, но не этот верификатор.
- **Возражать, а не соглашаться по умолчанию** — включая возражения против правил здесь.
- **Комментарий обязателен там, где код выглядит неправильным, но верен:** сохранённое из миграции
  поведение, намеренно оставленный баг, ограничение внешнего контракта или платформы, неявное
  семантическое отличие в граничных случаях (переполнение, timezone, locale, округление, кодировка).
  Одна-две строки: неожиданный факт, затем причина.
- Изменение обязано затронуть другие файлы — обновить их без вопросов; возможно затрагивает —
  сказать с конкретикой. Не оставлять кодовую базу несогласованной.

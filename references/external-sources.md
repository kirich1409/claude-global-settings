# Внешние источники

## Что здесь есть кроме web

Каналы существуют классами; какой инструмент закрывает класс — зависит от стека и от того, что
установлено на машине. Обнаруживать доступное (CLI платформы, MCP, локальный кэш сборки), а не
считать канал отсутствующим по умолчанию.

| Класс канала | Для чего |
|---|---|
| Сорсы зависимости на pinned-версии | реальный API той версии, что собирается, без интерпретации |
| Сорсы любой версии из реестра артефактов | API версии, к проекту не подключённой — сравнение и bump |
| CLI и bundled-инструменты платформы | курируемая документация и guides вендора, тулинг окружения |
| Code search вендора платформы | исходники самой платформы по версиям, плюс usages platform-API |
| OSS code search | usages символа по всему открытому коду |

`WebFetch` по rendered GitHub-страницам не использовать — брать raw.

## Как обнаружить канал

Один проход до первого запроса вовне, а не догадка по памяти:

1. **Пакетный менеджер проекта** — по манифесту (`build.gradle*` / `settings.gradle*`, `package.json`,
   `Cargo.toml`, `Package.swift`, `pyproject.toml`, `go.mod`). Он задаёт форму координаты и то, какой
   реестр вообще имеет смысл спрашивать.
2. **Что подключено в этой сессии** — MCP-серверы и CLI на PATH, закрывающие классы из таблицы:
   отдающие сорсы pinned-версии, метаданные реестра (последняя версия, CVE, лицензия, транзитивы,
   BOM, EOL), сканер уязвимостей своей экосистемы. Проверять наличие, а не предполагать.
3. **Класс не закрыт ничем** — работать через оставшиеся каналы и сказать об этом явно.

Имена конкретных инструментов здесь не фиксируются намеренно: набор зависит от машины и от стека, и
живёт в правиле своего стека (для JVM — `~/.claude/references/jvm-dependencies.md`, для Android-платформы
— `~/.claude/rules/android-cli.md`).

Доступность канала — не гарантия, а предмет проверки: локальный кэш может быть пуст, MCP не
подключён, публичный code search заблокирован сетевой политикой. Целый класс каналов недоступен —
сказать это явно, чтобы сниженная уверенность была видимой.

Context7: один провал `resolve-library-id` — стоп, не гнаться за синонимами.

## Оценка доверия

Источник может быть формально primary, а содержимое — устаревшим, для другой версии или
галлюцинацией. Оценивать tier до того, как поверить.

| Tier | Что | Источники |
|---|---|---|
| **T1** ground truth | артефакт без интерпретации | сорсы зависимости, код проекта, official release artifact |
| **T2** official docs | вендорская документация, releases, changelogs | документация платформы, Context7 для официальных либ |
| **T3** aggregated/AI | может галлюцинировать | Context7 для community-либ без вендорской docs |
| **T4** random web | блоги, StackOverflow, туториалы | WebSearch, случайный WebFetch |

Tier принадлежит источнику, а не каналу: найденный через code search vendor-endorsed сэмпл — T1/T2,
случайный репо — T4.

**Память — не tier.** `MEMORY.md`, recalled facts и существующий код проекта фиксируют то, что было
верно на момент записи. Память — указатель «где смотреть», не факт.

**По умолчанию T1 + T2 параллельно** для любого Edit/Write с внешней библиотекой — базовый режим, а
не «при сомнении». T1-only допустим только с явным обоснованием: стабильная stdlib; уже виденный
символ на той же pinned-версии, подтверждённый сорсами; тривиальное использование. «Кажется
очевидным» обоснованием не является.

**Конфликты:** T1 vs T2 — следовать T1, отметить расхождение, при существенном gap предложить bump.
Два официальных расходятся — свежий changelog важнее старой docs-страницы; непонятно — поднять
вопрос, не выбирать молча.

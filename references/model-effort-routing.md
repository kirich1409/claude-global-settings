# Model и effort

Два независимых рычага, настраивать оба. **Model** задаётся за вызов параметром `model:` инструмента
Agent; по умолчанию `inherit` наследует модель сессии, а сессия идёт на **sonnet** — значит промах
теперь стоит не денег, а качества. У встроенного `general-purpose` frontmatter нет, поэтому `model`
ему задаётся явно в каждом вызове и выбирается по задаче; встроенные `Explore` и `Plan` не
используются вовсе — вместо них свои `explorer` (haiku) и `planner` (opus/high), несущие оба рычага
конфигом. **Effort** за вызов не задаётся — поля `effort` в схеме Agent нет: он берётся из frontmatter
`effort:` агента, иначе наследуется из сессии. Отсюда следствие: назначить effort встроенному агенту
нельзя, нужна конкретная глубина — брать своего агента с прописанным effort. У Haiku рычага effort
нет вовсе, назначение ему effort вызывает ошибку.

Что несут свои агенты во frontmatter (оба рычага, в вызове не дублировать):

| Модель / effort | Агенты |
|---|---|
| opus / high | `planner`, `synthesizer`, `architecture-expert`, `debugging-expert`, `security-expert`, `performance-expert`, `ux-expert`, `business-analyst`, `spec-author` |
| opus / low | `dependency-evaluator` |
| fable / xhigh | `hard-case-arbiter` |
| sonnet / medium | `code-reviewer`, `code-simplifier`, `error-handling-reviewer`, `test-quality-reviewer`, `kotlin-engineer`, `compose-developer`, `swift-engineer`, `swiftui-developer`, `build-engineer`, `devops-expert`, `docs-writer`, `claude-config-engineer`, `manual-tester` |
| sonnet / low | `source-researcher`, `spike-runner` |
| haiku | `explorer`, `mech-worker`, `oss-scout`, `gh-project-manager` |

Цена переключения модели сессии, из-за которой рычаг — выбор агента, а не `/model`: turn сразу после
смены даёт `cache_creation` ~226k против ~8k у обычного, `cache_read` падает 266k → 23k (замер по
транскриптам 2026-08-05, n=2 — знак уверенный, величина ориентировочная).

Эвристика:

- Механическое, поиск, lookup, admin CRUD → **haiku**.
- Реализация, рефакторинг, code review, ручное QA, build engineering → **sonnet** либо **opus** на
  низком effort.
- Планирование, архитектура, security/perf/UX-ревью, отладка первопричины → **opus** на высоком effort.
- Сомневаешься между соседними уровнями — брать меньший и поднимать при первом сбое. Ошибка в
  сторону дешёвой модели видна сразу, ошибка в сторону дорогой невидима и оплачивается всегда.

По умолчанию haiku, без раздумий: поиск по коду и «где используется X» (`explorer`); чтение issue, PR
и комментариев, читающие `gh`-запросы; рутинные git-операции; переносы файлов, переименования,
механические замены по known-паттерну (`mech-worker`); сбор фактов из логов по заданному шаблону;
проверка «существует ли файл или символ».

Повышать модель — когда задача требует суждения (разрешение конфликта по смыслу, диагностика
причины, выбор между вариантами), а не «на всякий случай». Opus не оправдан на исполнении уже
принятого решения.

## Haiku на многосоставных задачах

Haiku надёжен на узкой атомарной подзадаче, но на многофазной **недоделывает**: выполняет первую
часть и останавливается, списывая остальное на «следующий шаг». Плюс склонен к тонким ошибкам
корректности, замаскированным собственным зелёным тестом (реальный кейс: обрезал `Double` до `Int`
при конверсии длительности и зашил обрезанное значение в тест).

Поэтому: Haiku давать атомарную единицу работы; многофазное декомпозировать до атомов либо вести на
sonnet+. Вывод Haiku верифицировать независимо — его зелёный тест корректности не доказывает. В
брифе перечислять все обязательные части явно и указывать, что остановка после первой = невыполнение.

## Неочевидная маршрутизация

Фиксированной таблицы «задача → агент» нет: harness перечисляет доступных в этом проекте агентов с
описаниями — подбирать по ним, затем применять эвристику выше. Не выводится из описаний:

- Планирование, архитектура и синтез → агент `planner` (opus/high конфигом) или профильный эксперт;
  главная сессия на sonnet держит постановку задачи и приёмку результата, но не сам reasoning.
  Превратить принятое решение в рецензируемый план-документ — скилл `/write-plan`.
- Security / performance / UX / code review → профильный **expert agent**, никогда не главная сессия.
- Долгие сборки, тесты и CI → **general-purpose в фоне**, не блокировать главную сессию.
- Правки конфигурации `~/.claude` → **claude-config-engineer**: несёт обязательные верификаторы и
  конвенции репо.
- Эмпирический спайк («проверь, что X реально работает») → **spike-runner**: минимальный
  различающий запуск, вердикт CONFIRMED/REFUTED/INCONCLUSIVE.
- Работа с PR, issue или доской → скилл `drive-to-merge` и идемпотентный toolkit
  `$HOME/.claude/scripts/gh/`. Никогда не блокироваться на `gh run watch` / `gh pr checks --watch`.

# Worktree — размещение и дисковая политика

Создавать в `<корень репо>/.worktrees/<slug>`
(`git worktree add -b <branch> .worktrees/<slug> origin/<base>` из корня). Убедиться, что каталог
игнорируется: `.worktrees/` в `.gitignore`, либо `.git/info/exclude` локально, если правка
tracked-файлов сейчас нежелательна. `git clean -fdx` в корне снесёт и ignored worktree — при живых
добавлять `-e .worktrees`. Не создавать worktree внутри worktree.

**Незанятые worktree не держать:** worktree крупного проекта вместе с кэшами сборки стоит десятки
гигабайт.

Когда одноразовость очевидна — чистить автономно и отчитаться постфактум, назвав путь и ветку:

- PR смержен, незакоммиченного нет → `git worktree remove <path>` + `git branch -D <branch>`. При
  squash-merge ветка формально «не смержена» по SHA — это ожидаемо.
- Remote-tracking ветка исчезла (`gone` в `git branch -vv`) → удалить.
- Пользователь свернул работу, а worktree этой сессии выглядит законченным → удалить и упомянуть
  в завершающем сообщении.

Спрашивать только когда есть незакоммиченные или незапушенные изменения, которых нет нигде больше.
Массовая уборка — скилл `worktree-cleanup`. Пропускать всё это, если чекаут основной, работа в
процессе или worktree создан только что.

# Гейт покрытия тестами

Минимум, применимый к любому изменению исходника. Полная стратегия верификации — скилл `verification`; здесь только то, что должно быть под рукой у всех, кто читает и правит код, включая ревьюеров.

**Изменённый публичный символ проверяется тестом.** «Публичный» = Kotlin без `@internal`/`private`, Swift `public`/`open`, TS `export`.

Тест не нужен для тривиального: чистые носители данных (`data class`, Swift `struct` только с хранимыми свойствами, TS interfaces, enums, type aliases), builder DSL без логики, реэкспорт уже покрытого символа.

**Нет изменения поведения → нет нового теста.** Перемещение файла, переименование, переупаковка, правка только импортов — это не изменение символа: существующие тесты плюс зелёная сборка уже его покрывают. Добавлять unit-тест поверх перемещения без логики — избыточное тестирование, такой же шум, как избыточное редактирование. Гейт срабатывает на изменение поведения или сигнатуры, но не местоположения.

**Кто сломал тест — чинит в том же PR.** `@Ignore` / `xit` / `t.Skip` только со ссылкой на отслеживаемую задачу в аннотации (`@Ignore("flaky on iOS 17 — JIRA-1234")`). Skip без задачи — нарушение гейта.

**Баг-фикс начинается с падающего теста.** Сначала увидеть тест красным — это доказывает, что он проверяет именно сломанное поведение, — затем чинить и увидеть зелёным. Тест, который никогда не наблюдали красным, не доказывает ничего.

**Первопричина, а не подавление.** Прежде чем обернуть падающее место в try/catch, добавить null-guard или `@Suppress` — проверить, корректно ли вообще то, что здесь падает. Если defensive-обёртка и есть весь фикс — это красный флаг: она допустима поверх устранённой причины, не вместо. Подавление не должно быть молчаливым; чинить все экземпляры паттерна, а не только тот, что в трейсе.

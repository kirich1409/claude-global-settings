# Зависимости

Никогда не добавлять новую зависимость без явного одобрения пользователя. Использовать то, что уже
есть в проекте; новая — единственный разумный вариант, значит предложить и дождаться согласия.

Читать исходники JVM-зависимости через `ksrc`, а не рытьём в `.gradle/`.

## Plan-stage gate

Добавление новой зависимости или плагина и обновление существующей — plan-stage решение, а не
деталь реализации. План нельзя финализировать, а реализацию начинать, пока библиотека не изучена и
версия не верифицирована. Правило одинаково для библиотек и для Gradle/Maven плагинов.

Для каждой зависимости план содержит четыре пункта в этом порядке:

1. **Идентификация.** Точный `groupId:artifactId` (или plugin id, или `name@registry`) плюс роль
   одной строкой: что делает, зачем нужна, почему существующие зависимости не покрывают задачу.
2. **Свежесть.** Последняя стабильная версия через `maven-mcp:latest-version` (для non-Maven —
   `npm view <pkg> version`, `pip index versions`, `cargo search`). Формат: «latest stable: X.Y.Z».
   Последняя версия pre-release, а стабильная старше — брать стабильную и отметить расхождение.
   Не пиннить версию потому, что она была в сниппете или в training data.
3. **Уязвимости.** `maven-mcp:check-deps-vulnerabilities` для выбранной координаты (или `npm audit`,
   `pip-audit`, `cargo audit`). Любой CVE или GHSA — остановить план, сообщить severity, advisory ID
   и версию с исправлением, предложить альтернативу. «Предупреждений нет» тоже результат, указывать
   явно.
4. **Изучение API.** Прочитать реальную библиотеку: JVM/Kotlin — `ksrc` на разрешённой версии,
   Android — плюс `android docs`, прочее — Context7 или официальные доки. План должен показывать,
   что интеграция использует текущий API, а не запомненную сигнатуру. При major-обновлении или для
   evolving-библиотеки (Ktor, Room, Compose, AGP, Hilt, kotlinx.*) — ещё
   `maven-mcp:dependency-changes <old> <new>` с breaking changes и migration notes в плане.

Блок в плане:

```
Dependency: io.example:foo-bar  — role: <one line>
- latest stable: 1.4.2 (no advisories)
- API: studied via ksrc, entry points: FooBar.create(...), uses kotlinx.coroutines Flow
- Bump diff (1.2.0 → 1.4.2): no breaking changes in public API
```

Нет такого блока — план не готов, реализация не начинается.

**На этапе реализации** версия уже утверждена планом. Задача реализующего агента — подтвердить, что
разрешённая версия совпадает с планом, и внести правку. Молча менять версии нельзя; нужен повторный
прогон проверки свежести — сообщить в главную сессию.

**Не Maven Central** — явно указать в плане использованный экосистемный сканер. Четыре пункта
обязательны независимо от стека.

# Зависимости

Никогда не добавлять новую зависимость без явного одобрения пользователя. Использовать то, что уже
есть в проекте; новая — единственный разумный вариант, значит предложить и дождаться согласия.

Исходники зависимости читать инструментом, отдающим сорсы pinned-версии ([[external-sources]]), а
не поиском по кэшу пакетного менеджера.

## Plan-stage gate

Добавление новой зависимости или плагина и обновление существующей — plan-stage решение, а не
деталь реализации. План нельзя финализировать, а реализацию начинать, пока библиотека не изучена и
версия не верифицирована. Правило одинаково для библиотек и для плагинов системы сборки.

Для каждой зависимости план содержит четыре пункта в этом порядке:

1. **Идентификация.** Точная координата в форме своего реестра плюс роль одной строкой: что делает,
   зачем нужна, почему существующие зависимости не покрывают задачу.
2. **Свежесть.** Последняя стабильная версия — запросом к реестру, а не по памяти. Последняя версия
   pre-release, а стабильная старше — брать стабильную и отметить расхождение. Не пиннить версию
   потому, что она была в сниппете или в training data.
3. **Уязвимости.** Прогнать по выбранной координате сканер уязвимостей своей экосистемы. Любой CVE
   или GHSA — остановить план, сообщить severity, advisory ID и версию с исправлением, предложить
   альтернативу. «Предупреждений нет» тоже результат, указывать явно.
4. **Изучение API.** Прочитать реальную библиотеку на разрешённой версии, чтобы план показывал
   интеграцию с текущим API, а не с запомненной сигнатурой. При major-обновлении или для библиотеки
   в активной эволюции — ещё diff API между версиями с breaking changes в плане.

Нет такого блока — план не готов, реализация не начинается. Четыре пункта обязательны независимо от
стека; какой именно сканер и канал реестра использованы — указывать явно.

**На этапе реализации** версия уже утверждена планом: подтвердить, что разрешённая версия совпадает
с планом, и внести правку. Молча менять версии нельзя — нужен повторный прогон проверки свежести и
сообщение в главную сессию.

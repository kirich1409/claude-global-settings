# Делегирование

Делегировать по суждению, а не по правилу. Субагент оправдан на **крупной, самостоятельной, параллелизуемой** работе: широкое исследование по многим файлам, независимые треки, длинная сборка или прогон тестов, которые не должны занимать главный контекст. Работу, которая закрывается несколькими вызовами инструментов, делать самому — порождение агента под неё стоит дороже, чем экономит.

- Хватает одного субагента — запускать одного, а не нескольких.
- Не поручать субагенту перепроверку собственной работы.
- Ревью (security / performance / UX / архитектура) — профильному эксперту: ценность в независимой перспективе, а не в разгрузке контекста.
- Планирование, синтез и решения оставлять в главной сессии.

Skill-first: если установленный скилл покрывает задачу, использовать его — он знает нужную последовательность. Прямой вызов агента — когда скилла нет.

## Что субагент получает при старте

Проверено замером: субагент наследует иерархию `CLAUDE.md` и **безусловные** правила `~/.claude/rules/*.md`. Повторять их в prompt делегирования не нужно.

Не долетает автоматически:

- **`paths:`-scoped правила** — загружаются, когда агент прочитает подходящий файл. Если правило нужно ему раньше, назвать ключевой момент в prompt.
- **Explore и Plan** пропускают `CLAUDE.md` и правила целиком. Нужное им — класть в prompt. Для поиска по коду это означает, что `ast-index.md` до них не доходит никогда, хотя ищут в основном они. Готовый блок для вставки в prompt:

  > Use `ast-index` via Bash before Grep: `search "q"`, `file "Name"`, `class "Name"`, `usages "Name"`, `implementations "Name"`, `callers "fn"`. Grep only for regex or string-literal search, or when ast-index returns nothing. Before `Read` on a file over ~500 lines, run `ast-index outline <file>` and read only the targeted slice via `offset`/`limit`. On "Index not found" run `ast-index rebuild`; never silently fall back to Grep.
- **Скиллы** — агент с тулом `Skill` найдёт нужный сам; агенту без него содержимое скилла доставляется полем `skills:` в его frontmatter (preload, проверено).

В prompt делегирования: задача, релевантные пути, ограничения, ожидаемая форма вывода.

Обратное направление: **`description` агента резидентно в системном промпте главной сессии** — по нему выбирают, кому делегировать, поэтому оно в контексте до всякого спавна. При спавне грузится **тело** агента как его system prompt. Проверено наблюдением; в документации этого нет — `agent-development` задаёт длину 200–1 000 символов, но не говорит, в чей контекст и когда. Следствие: длина описания агента — постоянная плата за каждую сессию, и правдоподобное «описание приезжает вместе с агентом» ведёт к выводу, что сокращать его незачем.

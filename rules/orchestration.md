# Оркестрация

Главная сессия работает на **sonnet** и служит маршрутизатором: разбирает запрос, выбирает
исполнителя, принимает результат. Дорогая модель включается **выбором агента, а не переключением
сессии** — смена модели посреди работы перезаписывает prompt cache целиком. «Здесь нужно подумать»
означает вызвать агента с `model: "opus"`, а не поднять модель себе.

Делегировать по суждению о размере работы, а не по запрету на тип файла.

**Дефолт — делегировать.** Работа над задачей начинается с выбора исполнителя, а не с первого
Edit. Взять её себе — осознанное исключение под один из случаев ниже, и его называют вслух в
отчёте. «Я уже разобрался, быстрее сделать самому» исключением не является: главная сессия идёт на
sonnet, и работа, которая требовала суждения, окажется сделана слабее — тихо, без сообщения об
ошибке, потому что модель не сигнализирует о собственном потолке.

Снимают его только просьба пользователя (см. «Отмена делегирования» ниже) и запрет уровня харнеса.
Запрет в system prompt сильнее этих правил, но молча ему подчиняться нельзя: сказать пользователю,
что делегирование заблокировано, и работать напрямую — иначе бюджет уходит на дорогую модель
незаметно для него.

**Делает сама — закрытый список:** однострочную или механическую правку по уже известному
`file:line`; ориентационный Read и Bash; правку рабочих файлов процесса (`swarm-report/**`, файлы
плана, `MEMORY.md` и `memory/`, scratch-файлы, `~/.claude/**`); отладку первопричины; синтез плана
из резюме специалистов; итоговый ответ пользователю. Всё остальное — делегируется.

Список закрытый намеренно: прежняя формулировка («работа, закрывающаяся несколькими вызовами
инструментов») на практике пропускала многочасовую реализацию, потому что задача, которую модель
уже обдумала, кажется закрывающейся в пару правок.

**Делегирует:** крупную, самостоятельную, параллелизуемую работу — многофайловую реализацию и
рефакторинг; широкое исследование по многим файлам (→ `explorer`); долгие сборки, тесты и CI
(→ general-purpose в фоне); ревью security, performance, UX и архитектуры (→ профильный эксперт).

За главной сессией остаются **решение и приёмка**: сформулировать задачу, выбрать исполнителя,
задать критерий готовности, принять результат, ответить пользователю. Сам **reasoning уходит
opus-агенту** — на sonnet его больше не держат. Хватает одного субагента — запускать одного. Не
поручать субагенту перепроверку собственной работы.

**Opus-агент вызывается по списку, а не по оценке «а надо ли».** Оценку делает sonnet, и её ошибка
не видна: агент просто не будет вызван, а результат придёт уверенным и слабым. Поэтому без
раздумий делегируют на opus: построение плана реализации; проектирование архитектуры и выбор между
вариантами; отладку первопричины; security-, performance-, UX- и архитектурное ревью; сведение
находок независимых сборщиков без записанного алгоритма; разбор противоречий между заключениями
агентов, когда протокол их не разрешает.

Обратная граница столь же жёсткая: **агрегация по прописанному протоколу reasoning'ом не является**
и остаётся в главной сессии — шаг 4 `multiexpert-review`, агрегация `acceptance`. Критерий не в
слове «синтез», а в том, **записан ли алгоритм**: правила агрегации движка не переопределяемы, их
исполняет sonnet; там, где записаны только оси внимания, а решение по каждому пересечению выносится
заново, работает `synthesizer` — так устроена фаза 3 `research`, ради которой консорциум и
запускается.

**Думающему агенту нужен письменный вход.** Обычный субагент получает свою модель, но не наследует
диалог; `fork` наследует весь контекст сессии и **всегда идёт на модели родителя** — параметр
`model` у него игнорируется, то есть с sonnet-сессии opus через fork недостижим. Значит контекст,
накопленный в переписке, материализуется в файл (план, спека, `swarm-report/<slug>-debug.md`,
дифф) **до** вызова, иначе opus получит огрызок брифа и вернёт ответ на него.

Признак, что порог перейдён: работа перестаёт помещаться в голову целиком, требует читать много
файлов подряд или распадается на независимые треки. N правок в одном месте — одна работа; N правок
по всей кодовой базе — работа специалиста.

**Реализация фичи или багфикса целиком — не работа главной сессии.** Правка кода, к которой
прилагается тест, прогон сборки и цикл «упало → поправил», это единица для `kotlin-engineer` /
`compose-developer` / профильного инженера, даже когда она кажется мелкой и понятной: понятной она
выглядит ровно потому, что reasoning уже отработал. Главная сессия формулирует задачу, критерий
готовности и способ проверки — а потом принимает результат.

Счётчик вместо интуиции: **закрытие одной задачи трекера ≈ один субагент.** Три задачи подряд,
сделанные своими руками, — сигнал, что порог давно перейдён, а не признак продуктивности. Дорогая
модель, вручную гоняющая `sed` и пересобирающая APK, тратит бюджет на то, для чего есть sonnet.

**Исключения, когда делать самому дешевле:** отладка первопричины (нужен весь контекст сессии
разом), однострочная правка по уже известному file:line, и работа, которую пользователь явно
попросил не делегировать.

**Реализацию и L5 давать разными вызовами.** Навигация по живому UI — десятки вызовов `uiautomator
dump` + `input tap` с разбором координат на каждом шаге, и агент выбирает лимит инструментов ровно
на ней: три подряд оборвались фразой «теперь перехожу к проверке на устройстве», оставив работу
незакоммиченной. Агенту — реализация плюс механические проверки; L5 отдельным заходом
(`manual-tester` либо главная сессия, у которой к этому моменту уже есть координаты экранов).
Побочная выгода: L5 делает не тот, кто писал код.

**Два и больше агентов с правом записи одновременно — только с `isolation: "worktree"`.** Изолированный
worktree выдаётся не всегда: без него агенты работают в общем дереве и переключают в нём ветки друг у
друга. Read-only агенты (`explorer`, `planner`, `source-researcher`, ревьюеры и прочие с `disallowedTools`,
включающим `Edit`/`Write`) под правило не подпадают: они ничего не пишут, и заводить им worktree —
чистые накладные расходы. Правило про конкурирующие записи, а не про параллельность как таковую.
Наблюдаемый исход — незакоммиченные правки одного попадают в коммит другого, а его собственная ветка
остаётся пустой; ktlint при этом краснеет на чужих файлах, и агент честно списывает это на соседа.
Разведение по путям в prompt от этого не спасает: ветка общая, а не файлы.

**Skill-first:** задача покрывается установленным скиллом — использовать скилл, он знает правильную
последовательность агентов и моделей. Прямой Agent — fallback, когда скилла нет.

**Отмена делегирования.** «do it yourself», «don't delegate», «write it by hand» → главная сессия
работает напрямую до завершения текущей задачи, затем возвращается в режим оркестратора.

## Model и effort

Два независимых рычага, настраивать оба. **Model** задаётся за вызов параметром `model:`. Умолчание
инвертировалось вместе с моделью сессии: раньше `inherit` молча оставлял дорогую модель, теперь он
молча оставляет **sonnet** — и промах стоит уже не денег, а качества. **Effort** за вызов не
задаётся: берётся из frontmatter `effort:` агента или наследуется из сессии; **у Haiku рычага
effort нет, назначение ему effort вызывает ошибку**.

**Встроенные `Explore` и `Plan` не использовать — вместо них `explorer` и `planner`.** Отключить
встроенных нельзя, и тем они опасны: frontmatter у них нет, поэтому оба рычага молча наследуются из
сессии, а `CLAUDE.md`, rules и `MEMORY.md` они не видят вовсе. Свои несут оба рычага конфигом и
наследуют правила как обычный субагент.

`general-purpose` остаётся в ходу и frontmatter тоже не имеет — ему `model` задаётся **явно и по
задаче**: сборка, тесты, сбор фактов по шаблону → `sonnet`; работа с суждением → `opus`.

`effort` параметром вызова не передаётся — **в схеме инструмента Agent такого поля нет**. Значит
встроенному агенту effort не назначить: нужна конкретная глубина рассуждения — брать своего агента,
у которого она прописана. В Workflow-скрипте рычаг есть — `opts.effort`.

- Механическое, поиск, lookup, admin CRUD → **haiku**.
- Реализация, рефакторинг, code review, ручное QA, build engineering → **sonnet** либо **opus** на
  низком effort.
- Планирование, архитектура, security/perf/UX-ревью, отладка первопричины → **opus** на высоком effort.
- Сомневаешься между соседними уровнями — брать меньший и поднимать при первом сбое. Ошибка в
  сторону дешёвой модели видна сразу, ошибка в сторону дорогой невидима и оплачивается всегда.

**Haiku на многосоставных задачах недоделывает:** выполняет первую часть и останавливается, списывая
остальное на «следующий шаг», плюс склонен к тонким ошибкам корректности, замаскированным
собственным зелёным тестом. Давать ему атомарную единицу работы; многофазное декомпозировать до
атомов либо вести на sonnet+. Его вывод верифицировать независимо.

Полная эвристика, список задач по умолчанию на haiku и неочевидная маршрутизация по агентам —
`~/.claude/references/model-effort-routing.md`.

## Что наследует субагент

Проверено замером: субагент наследует `CLAUDE.md`, `MEMORY.md` и все **безусловные**
`~/.claude/rules/*.md` (без frontmatter `paths:`). Повторять их в prompt делегирования не нужно.

Четыре пробела, которые не долетают автоматически:

- **`paths:`-scoped правила** загружаются лениво, при чтении подходящего файла. Если субагент
  должен соблюдать такое правило раньше — назвать ключевой момент в prompt или дать путь к файлу.
- **`~/.claude/references/**`** не загружается никогда и ни у кого — это площадка прогрессивного
  раскрытия. Нужен субагенту конкретный справочник — дать путь в prompt.
- **Встроенные `Explore` и `Plan`** пропускают `CLAUDE.md`, rules и `MEMORY.md` целиком — ровно
  поэтому они заменены своими `explorer` и `planner`, которые наследуют всё перечисленное
  (проверено спайком 2026-08-05: переопределённый агент цитирует принцип из `CLAUDE.md` и видит
  правило про `ast-index`). Вызвал встроенный вопреки правилу — придётся вкладывать конвенции
  в prompt руками.
- **`tools:` во frontmatter отсекает MCP и `ToolSearch`.** Проверено спайком: агент с
  `tools: Read, Glob, Grep, Bash` не видит ни одного MCP-инструмента и не может дотянуться до них
  через `ToolSearch`; агент без этого поля вызывает их свободно. Список — whitelist целиком, а не
  добавка к дефолту. Агенту, которому нужен внешний канал (реестр зависимостей, docs, code search),
  инструментарий ограничивать через `disallowedTools`, иначе он молча теряет канал и уходит в веб.

В prompt делегирования: задача, релевантные пути, ограничения, ожидаемая форма вывода, плюс
scoped-правило или путь к справочнику, если применимо.

## Антипаттерны

- Вызывать встроенные `Explore` и `Plan` вместо `explorer` и `planner`: правил они не видят, модель
  и effort берут из сессии, то есть на sonnet-сессии планирование тихо идёт на sonnet.
- Держать reasoning в главной сессии, потому что «я уже разобрался»: разобрался sonnet, и его
  потолок не виден по ответу.
- Сокращать triggered reviewer panel. Профиль определяет набор правилами — использовать весь.
  «Эта область уже разобрана в прошлом ревью другого артефакта» основанием не является: research,
  spec и test-plan — разные тексты с разными failure modes.

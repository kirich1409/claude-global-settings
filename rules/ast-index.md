# Поиск по коду

`ast-index` — основной инструмент навигации по символам: найти класс, символ, использования,
реализации, вызывающих, иерархию, зависимости модуля, outline файла. Полный синтаксис —
`ast-index --help`.

Разделение инструментов:

- **ast-index** — любой поиск «найти X» по имени символа или файла.
- **LSP** — семантическое разрешение типов: hover, точное определение, generics, точная иерархия вызовов.
- **Grep** — строковые литералы, regex, текст комментариев, значения конфигов, сообщения логов.

Жёстко:

- Не искать Grep'ом класс, функцию, интерфейс, переменную или любой символ по имени.
- Не искать Glob'ом исходный файл по имени класса или модуля.
- Не запускать Grep «для полноты» после того, как ast-index вернул результаты.
- Перед `Read` файла длиннее ~500 строк — `ast-index outline <file>`, затем читать нужный срез
  через `offset`/`limit`.

«Index not found» или `⚠ AST INDEX NOT AVAILABLE` в session reminder → `ast-index rebuild` через
Bash (работает из любого агента, включая `explorer`), затем повторить поиск. Не переходить на Grep и
не пропускать поиск.

Индекс поддерживается хуками автоматически: SessionStart делает `update` или `rebuild` и поднимает
watcher, EnterWorktree инициализирует свежий worktree, SessionEnd останавливает watcher. Ручной
`update` в обычной работе не нужен.

# Git

- **Свежая база:** перед ветвлением, пушем и открытием PR — `git fetch` и rebase на актуальную базу. После rebase, подтянувшего чужие коммиты, перезапустить проверки, релевантные изменениям.
- **Ветки:** `feature/...` (новое поведение), `fix/...` (баг), `chore/...` (без изменения продуктового поведения). Kebab-case, английский, префикс по сути изменения, а не по размеру.
- **Коммиты:** один атомарный коммит на логическую единицу; крупная задача — коммит на этап. Сообщение в повелительном наклонении, английский, заголовок ≤72 символов, без `feat:`/`fix:`-префиксов. Тело — когда контекст неочевиден.
- **Worktree:** создавать в `<корень репо>/.worktrees/<slug>`. Убедиться, что каталог игнорируется (`.worktrees/` в `.gitignore`, либо локально в `.git/info/exclude`). `git clean -fdx` в корне снесёт и ignored worktree — при живых добавлять `-e .worktrees`. Worktree, создаваемые harness'ом, выбирают путь сами.
- **Пуш feature-ветки — рутина:** создание ветки, коммиты, push и открытие draft PR подтверждения не требуют. `--force-with-lease` / `--force-if-includes` тоже. Подтверждение нужно для промоции PR в ready и слияния в дефолтную ветку.
- **Перед пушем** прогонять проверки, релевантные изменениям (тронул сборку — собрать, тронул тесты — прогнать). Draft-статус не оправдание; единственная причина пропустить — осознанно неполная работа.
- **Checkpoint перед крупным рефакторингом:** `git add -A && git commit -m "checkpoint: <что меняется>"`. Восстановление — `Esc Esc` или `git reset --hard HEAD`.

## Очистка worktree

Диск ограничен, Android-worktree стоят десятки гигабайт с кэшами. Когда одноразовость очевидна — чистить автономно и отчитаться постфактум, назвав путь и ветку:

- PR смержен, незакоммиченного нет → `git worktree remove` + `git branch -D`. При squash-merge ветка формально «не смержена» по SHA — это ожидаемо.
- Remote-tracking ветка исчезла (`gone` в `git branch -vv`) → удалить.
- Пользователь свернул работу, а worktree выглядит законченным → удалить и упомянуть в завершающем сообщении.

Ветку не жалко, но её ещё нет на remote — сначала запушить, чтобы стала восстановимой, затем удалить. Спрашивать только когда есть незапушенные изменения, которых нет нигде больше. Пропускать всё это, если чекаут основной, работа в процессе или worktree создан только что.

# Git

- **Ветки:** `feature/...` (новое поведение), `fix/...` (баг), `chore/...` (без изменения
  продуктового поведения). Kebab-case, английский, префикс по сути изменения, а не по размеру.
- **Коммиты:** один атомарный коммит на логическую единицу, крупная задача — коммит на этап.
  Сообщение в повелительном наклонении, английский, заголовок ≤72 символов, **без
  `feat:`/`fix:`-префиксов**. Тело — когда контекст неочевиден.
- **Force push:** обычный `--force` запрещён. `--force-with-lease` / `--force-if-includes`
  разрешены без подтверждения.
- **Git hooks:** не обходить (`--no-verify`, `--no-gpg-sign`) без явной инструкции. Сбой hook →
  первопричина.
- **Перед пушем** прогонять проверки, релевантные изменениям. Draft-статус не оправдание;
  единственная причина пропустить — осознанно неполная работа.
- **Push feature-ветки — рутина:** на выделенной ветке создание, коммиты, push и открытие draft PR
  подтверждения не требуют. Подтверждение нужно для обычного `--force`, промоции PR в ready и
  слияния в дефолтную ветку.

## Worktree

Создавать в `<корень репо>/.worktrees/<slug>`
(`git worktree add -b <branch> .worktrees/<slug> origin/<base>` из корня). Убедиться, что каталог
игнорируется: `.worktrees/` в `.gitignore`, либо `.git/info/exclude` локально, если правка
tracked-файлов сейчас нежелательна. `git clean -fdx` в корне снесёт и ignored worktree — при живых
добавлять `-e .worktrees`. Не создавать worktree внутри worktree.

**Незанятые worktree не держать:** worktree крупного проекта вместе с кэшами сборки стоит десятки
гигабайт.
Когда одноразовость очевидна — чистить автономно и отчитаться постфактум, назвав путь и ветку:

- PR смержен, незакоммиченного нет → `git worktree remove <path>` + `git branch -D <branch>`. При
  squash-merge ветка формально «не смержена» по SHA — это ожидаемо.
- Remote-tracking ветка исчезла (`gone` в `git branch -vv`) → удалить.
- Пользователь свернул работу, а worktree этой сессии выглядит законченным → удалить и упомянуть
  в завершающем сообщении.

Спрашивать только когда есть незакоммиченные или незапушенные изменения, которых нет нигде больше.
Массовая уборка — скилл `worktree-cleanup`. Пропускать всё это, если чекаут основной, работа в
процессе или worktree создан только что.

## Модель доставки задаёт репозиторий

Закрыта ли дефолтная ветка для прямых коммитов и нужен ли PR — определяют branch protection
репозитория и инструкции проекта, а не глобальные правила. Конвенции выше — дефолты. Для
`~/.claude` модель описана в [[claude-repo-sync]]: прямые коммиты в `main`.

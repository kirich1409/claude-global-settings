# Git

- **Ветки:** `feature/...` (новое поведение), `fix/...` (баг), `chore/...` (без изменения
  продуктового поведения). Kebab-case, английский, префикс по сути изменения, а не по размеру.
- **Коммиты:** один атомарный коммит на логическую единицу, крупная задача — коммит на этап.
  Сообщение в повелительном наклонении, английский, заголовок ≤72 символов, **без
  `feat:`/`fix:`-префиксов**. Тело — когда контекст неочевиден.
- **Force push:** обычный `--force` запрещён. `--force-with-lease` / `--force-if-includes`
  разрешены без подтверждения.
- **Git hooks:** не обходить (`--no-verify`, `--no-gpg-sign`) без явной инструкции. Сбой hook →
  первопричина.
- **Перед пушем** прогонять проверки, релевантные изменениям. Draft-статус не оправдание;
  единственная причина пропустить — осознанно неполная работа.
- **Push feature-ветки — рутина:** на выделенной ветке создание, коммиты, push и открытие draft PR
  подтверждения не требуют. Подтверждение нужно для обычного `--force`, промоции PR в ready и
  слияния в дефолтную ветку.

- **Worktree:** размещать в `<корень репо>/.worktrees/<slug>`, каталог держать в ignore. Дисковая
  политика и правила автономной уборки — `~/.claude/references/git-worktree.md`.

Закрыта ли дефолтная ветка для прямых коммитов и нужен ли PR — определяют branch protection
репозитория и инструкции проекта, а не эти конвенции. Для `~/.claude` модель описана в
[[claude-repo-sync]]: прямые коммиты в `main`.

# Model и effort

Два независимых рычага. **Model** задаётся за вызов параметром `model:` инструмента Agent (`inherit` по умолчанию молча оставляет дорогую главную модель — ставить явно). **Effort** берётся из frontmatter `effort:` агента или наследуется из сессии; у Haiku рычага effort нет.

Эвристика:

- Механическое, поиск, lookup, admin CRUD → **haiku** (агенты `Explore`, `mech-worker`).
- Реализация, рефакторинг, code review, ручное QA, build engineering → **sonnet**, либо **opus** на низком effort.
- Планирование, архитектура, security/perf/UX-ревью, отладка первопричины → **opus** на высоком effort.
- Сомневаешься между соседними уровнями — брать меньший и поднимать при первом сбое.

Ошибка в сторону дешёвой модели видна сразу и стоит дёшево; ошибка в сторону дорогой невидима и оплачивается всегда.

**Effort пересвипывать под текущую модель, а не переносить с прошлой.** Значения, подобранные под Opus 4.x, на Opus 5 не переносятся: там `high` — дефолт и разумный старт, `low`/`medium` применимы шире, чем кажется, а `xhigh` — для по-настоящему длинной агентной работы. Проверять на своих задачах, а не по памяти.

## Haiku на многосоставных задачах

Замечено на практике: Haiku надёжен на узкой атомарной подзадаче, но на многофазной **недоделывает** — выполняет первую часть и останавливается, списывая остальное на «следующий шаг». Плюс склонен к тонким ошибкам, замаскированным собственным зелёным тестом (реальный кейс: обрезал `Double` 17.4s до `Int` и зашил обрезанное значение в тест — тест проходит, поведение неверное).

Поэтому: Haiku давать атомарную единицу работы; многофазное либо разбивать до атомов, либо вести на sonnet+. Вывод Haiku верифицировать независимо — его зелёный тест корректности не доказывает. В брифе для Haiku перечислять все обязательные части явно и указывать, что остановка после первой = невыполнение задачи; риск это снижает, но не снимает.

## Неочевидная маршрутизация

- Правки конфигурации `~/.claude` → **claude-config-engineer**: несёт конвенции репо и обязательные верификаторы.
- Эмпирический спайк («проверь, что X реально работает») → **spike-runner**: минимальный различающий запуск, вердикт CONFIRMED/REFUTED/INCONCLUSIVE.
- Работа с PR/issue/доской → скилл `drive-to-merge` и идемпотентный toolkit `$HOME/.claude/scripts/gh/`. Никогда не блокироваться на `gh run watch` / `gh pr checks --watch`.
- Крупная самостоятельная единица реализации → `codex:codex-rescue` — модель и границы делегирования в [[codex-delegation]].

Фиксированной таблицы «задача → агент» нет: harness перечисляет доступных в этом проекте агентов с описаниями — выбирать по ним.

# Описания скиллов и агентов

`description` во frontmatter резидентно в контексте каждой сессии — и у скилла, и у агента. Тело грузится только после того, как выбор сделан. Значит описание несёт ровно сигнал выбора: по нему модель решает «этот инструмент или не этот», и ничего больше делать не обязано.

Проверено эмпирически, а не выведено: описания всех агентов из `~/.claude/agents/` присутствуют в системном промпте главной сессии. Правдоподобное «описание агента грузится при спавне» — неверно; при спавне грузится **тело** агента как его system prompt.

## Бюджеты

Наборы для скиллов и агентов разные, путать их нельзя.

| | Агенты | Скиллы |
|---|---|---|
| Рекомендуемая длина | **200–1 000 символов** | **~100 слов** на `name` + `description` |
| Жёсткий лимит | 10–5 000 символов (валидация) | 1 536 символов на `description` + `when_to_use` |
| При превышении | валидация отвергает | обрезается в листинге |

Бюджет всего листинга скиллов — **1% окна модели**. При переполнении Claude Code укорачивает описания, начиная с наименее используемых скиллов, так что часто вызываемые сохраняют полный текст. Поднимается настройкой `skillListingBudgetFraction` (или `SLASH_COMMAND_TOOL_CHAR_BUDGET` для фиксированного размера) — но это увеличивает резидентный контекст, а не уменьшает; применять осознанно.

Отдельного бюджета на суммарный листинг агентов в документации нет — только валидационный потолок на одно описание.

## Что в описании, а что в теле

В описании:

- предмет ответственности — что инструмент делает;
- 2–4 триггерных сценария прозой, разными формулировками одного намерения; для скиллов — точные фразы, которые скажет пользователь;
- граница с ближним соседом там, где путаница реальна и дорога («НЕ использовать для: …»);
- для агентов — указатель на раздел «Когда вызывать» в теле.

В тело, а не в описание:

- метод работы: через какие API, паттерны и инструменты агент делает свою работу;
- перечисление технологий, если оно не различает соседних агентов;
- проработанные сценарии и примеры вывода;
- любые инструкции исполнения — до выбора они бесполезны, после выбора тело уже загружено.

## Форма

Описание — от третьего лица: «This skill should be used when the user asks to …». Императив («Use this skill when…», «Использовать этого агента…») официальная документация помечает как ошибку для поля `description`. Тело — наоборот, императив для скиллов и второе лицо для системного промпта агента.

## Источники

- `code.claude.com/docs/en/skills.md` — потолок 1 536 символов, бюджет листинга 1%, порядок обрезки, настройки.
- Скилл `agent-development` официального плагина `plugin-dev` (маркетплейс `claude-plugins-official`), раздел «Description Validation» — диапазоны 10–5 000 и 200–1 000.
- Скилл `skill-development` того же плагина, раздел про трёхуровневую загрузку — «~100 words», третье лицо, шаблон триггерных фраз.

Цифры брать отсюда. Общий случай — принцип «утверждение о чужом инструменте из его источника правды» в `CLAUDE.md` и маршрутизация в скилле `research-sources`.

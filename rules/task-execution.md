# Выполнение задач

## Ждать по условию, а не по таймеру

Никогда не ждать фиксированным `sleep` в надежде, что состояние успеет измениться. Опрашивать реальный сигнал (файл появился, порт слушает, лог содержит маркер, задача завершилась) в цикле с верхней границей. Готовый хелпер: `$HOME/.claude/scripts/wait-for.sh [-t sec] [-i sec] -- cmd` — не писать цикл вручную.

Верхняя граница обязательна: по её достижении падать громко («условие X не наступило за Ns»), не продолжать молча. Единственный допустимый фиксированный `sleep` — короткий шаг внутри poll-цикла.

## Блокирующие ошибки

Сообщить, диагностировать, попытаться устранить, отчитаться о том, что сделано. Если одной попытки не хватило — остановиться и спросить, как продолжать. Расследование без блокера идёт молча, с одним отчётом в конце.

## Большой вывод

Команды с потенциально большим выводом (прогоны тестов, логи сборки, деревья зависимостей) пускать через context-mode: PreToolUse-хук обрабатывает Bash автоматически, для больших результатов MCP-инструментов вызывать `mcp__plugin_context-mode_context-mode__execute` явно.

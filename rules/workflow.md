# Рабочий процесс

## Шаг 0: триаж

До всего остального классифицировать входящее и выбрать маршрут. Идти сверху вниз, остановиться на
первой подходящей ветке.

1. **Тривиально → делать сразу.** Однострочное или механическое изменение с очевидным результатом,
   правка только доков либо конфига без логики. Мимо всех gates, без research и плана.
2. **Вопрос, а не сборка → ответить или исследовать.** Копание по своей кодовой базе — Explore;
   широкое многоисточниковое — скилл `research`.
3. **ЧТО строить не понято → сначала понять, потом зафиксировать.** Не понимаем, КАК это делается
   → `research`, его выход — понимание, не код. Понимаем ЧТО, но нужен прочный контракт для
   автономной реализации → `/write-spec`. Конвейер крупной непонятой фичи: `research` →
   `/write-spec` → декомпозиция → план → реализация, где каждое звено опускается, если его вход
   уже есть.
4. **Слишком крупно для одной единицы → декомпозировать** и прогнать каждую часть через триаж заново.
5. **Решено и помещается → оценить сложность.** Многофайловое, рискованное или с несколькими путями
   реализации → preparation gate и `/write-plan`. Узкое, понятный путь, известный стек → сразу
   реализация.
6. **Определить тип задачи → `references/task-types.md`:** источник истины, минимальный уровень
   пирамиды, момент написания тестов, нужен ли baseline до изменений.

## Обязательные gates

**Preparation gate — до любой реализации.** Собрать три вывода, реально собранных, а не названных:

- **Источники истины** (что означает «готово»): spec/AC, baseline до изменений, макеты и скриншоты,
  debug-repro. Активно производить их — снимать скриншоты, поднимать окружение, фиксировать baseline
  до миграции. Чего нельзя сделать самому — спросить, назвав, что деградирует без этого.
- **Источники знаний** (как строить). Для любого Edit/Write с внешней библиотекой — **два канала
  параллельно**: артефакт разрешённой версии (сорсы, декларации, заголовки) отвечает, что API
  существует; вендорская документация — как им пользоваться сейчас. Только первый даёт
  компилируемый, но устаревший код; только второй — сигнатуру, которой в этой версии нет. Каналы,
  tier-модель доверия и reference implementations — `references/external-sources.md` и
  `references/verify-library-api.md`. Новая или обновляемая зависимость — `references/dependencies.md`
  (её plan-stage gate обязателен до финализации плана).
- **Тестируемость и декомпозиция:** оценить, насколько сложно верифицировать изменение, и
  предложить упрощения заранее; разбить задачу, слишком большую для одного плана.

Вопросы концентрировать в этой фазе; после сбора источников двигаться без лишних уточнений.

**Acceptance gate — `/acceptance`.** Единственный обязательный пост-имплементационный гейт, после
каждой реализации с кодом, до объявления задачи завершённой и до продвижения PR. Исполняет пирамиду
тремя блоками: механический (L0, L1a, L2), слои суждения (L1b — `code-reviewer` плюс экспертная
панель по триггерам, с циклом фиксов), device-блок (L3 → L4 → L5). Отдельного гейта качества кода
нет: он и есть слои суждения внутри `/acceptance`.

Исключение гейта: только доки, только конфиг без логики, однострочные механические правки.
Исключение снимает церемонию, но не верификацию: у конфига есть свой минимальный верификатор
(`validate-config`, schema, dry-run) — прогнать обязательно.

**PR promotion gate — `/create-pr --promote`** требует явного подтверждения пользователя. Открыть
draft PR — рутина.

## Потоки

**Нетривиальная фича:** preparation gate → реализация на feature branch в worktree, draft PR
заранее через `/create-pr --draft` → `/acceptance` → `/create-pr --promote`
(с подтверждением) → `/drive-to-merge`. Опционально `/multiexpert-review` для высокорисковых планов.

**Багфикс:** зафиксировать шаги воспроизведения в `swarm-report/<slug>-debug.md` — это источник
истины для `/acceptance`. Написать падающий тест, **увидеть его красным**, затем фикс → `/acceptance`
→ PR. Регрессионный тест не опционален; исключение по gate тестируемости всегда отслеживаемое.

**Исследовательское QA без spec:** вызвать `manual-tester` напрямую.

## Исполнение

- **Блокирующая ошибка:** уведомить, диагностировать, попытаться устранить автономно, отчитаться о
  сделанном. Одной попытки не хватило — остановиться и спросить. Расследование без блокера идёт
  молча, с одним отчётом в конце.
- **Первопричина, а не подавление симптома.** Defensive-обёртка, которая и есть весь фикс, — красный
  флаг: допустима только поверх устранённой причины. Чинить все экземпляры паттерна, не только тот,
  что в трейсе. Подавление не бывает молчаливым — проглоченная ошибка логируется. Подробности —
  `references/task-execution.md`.
- **Ждать по условию, а не по таймеру:** `$HOME/.claude/scripts/wait-for.sh [-t sec] [-i sec] -- cmd`.
  Верхняя граница обязательна. Фиксированный `sleep` допустим только шагом внутри poll-цикла.
- **Долгая многоэтапная задача начинается с файла состояния** в `swarm-report/`: он переживает сжатие
  контекста, чат — нет. Формат, набор файлов и правило перечитывания — `references/context-resilience.md`.

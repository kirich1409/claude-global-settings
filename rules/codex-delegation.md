# Делегирование реализации в Codex CLI

Плагин `codex` даёт субагента `codex:codex-rescue` (тулы: только Bash) и скилл `codex:rescue`. Под капотом — `codex-companion.mjs`, подкоманды `setup`, `review`, `adversarial-review`, `task [--background] [--write] [--resume-last|--resume|--fresh] [--model <model|spark>] [--effort <none|minimal|low|medium|high|xhigh>]`, `transfer`, `status`, `result`, `cancel`. Реализация идёт через `task --write` — файлы правит сам Codex в рабочем дереве. Проверено эмпирически: codex-cli 0.145.0, ChatGPT-логин активен, runtime поднимается по требованию.

Профиль агента — «rescue»: задуман под второй проход, диагностику и передачу крупной застрявшей задачи, а не как штатный реализатор. Использование его штатным реализатором для крупных единиц работы — осознанное решение пользователя от 2026-07-28.

## Когда делегировать

Codex — реализатор по умолчанию для **крупных самостоятельных единиц работы**: задача из плана целиком, слой фичи, самостоятельный модуль, длинный рефакторинг по готовому рецепту. Мелкие точечные правки — делать самому: спавн стоит дороже, чем экономит, та же логика, что в [[orchestration]].

## Роутинг моделей

Список из `~/.codex/models_cache.json`, приоритеты 1/2/3/7/16/23/26, по убыванию сложности задачи:

- сложное → `gpt-5.6-sol` (effort до `ultra`)
- среднее → `gpt-5.6-terra`, затем `gpt-5.6-luna`
- проще → `gpt-5.5`, `gpt-5.4`
- механическое → `gpt-5.4-mini`, `gpt-5.3-codex-spark`

Effort — независимый рычаг (`low|medium|high|xhigh|max|ultra`; у `luna` и ниже потолок `xhigh`). Сомневаешься между соседними моделями — брать меньшую и поднимать при первом сбое, как в [[model-effort-routing]].

Лимит Codex исчерпан → молча возвращаться на собственные модели и профильных агентов (`kotlin-engineer`, `swift-engineer`, `compose-developer`, `swiftui-developer`), сообщив пользователю о переключении. Это не повод останавливать работу.

## Что Codex не наследует

Ключевой пункт: до Codex не доходят ни `~/.claude/rules/*.md`, ни `CLAUDE.md` проекта. Он читает `AGENTS.md` репозитория и `~/.codex/AGENTS.md`. Следствие: стековые правила (`kotlin-style`, `coroutines`, `compose-style`, `swift-concurrency`, `swiftui-*`, `logging`, `code-style`) в prompt делегирования нужно называть явно — тем же способом, каким [[orchestration]] требует это для Explore и Plan.

## Верификация не делегируется

`/finalize`, `/acceptance` и CI-контракт остаются на стороне Claude. Вывод Codex верифицируется независимо: его зелёный прогон корректности не доказывает — та же дисциплина, что применяется к Haiku в [[model-effort-routing]].

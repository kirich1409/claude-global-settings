# Политики кода

- **Feature flags** не добавлять проактивно — это продуктовое решение. Задача явно подразумевает
  флаг — сначала спросить.
- **Breaking changes** вносить напрямую: обратная совместимость и миграция — ответственность
  пользователя, если он не попросил иначе. Для public API, схемы БД или CLI-интерфейса — уведомить
  перед тем, как продолжить.
- **Никогда не выбирать архитектурный подход молча, когда есть альтернативы.** Паттерн проекта
  очевиден — следовать ему; не ясен — представить варианты с компромиссами, рекомендовать с
  обоснованием и продолжить.

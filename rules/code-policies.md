# Политики кода

Стиль написания кода, комментарии и работа с legacy — `code-style.md`. Логирование целиком —
[[logging]], единственный источник; здесь ничего о нём не дублируется.

## Feature flags и конфигурация

- **Feature flags** не добавлять проактивно — это продуктовое решение. Задача явно подразумевает
  флаг — сначала спросить.
- **Конфигурация** следует существующему паттерну проекта. Паттерна нет — класть в выделенный
  конфиг-слой, без хардкоженных значений.

## Breaking changes

Вносить изменение напрямую: обратная совместимость и миграция — ответственность пользователя, если
он не попросил иначе. Для public API, схемы БД или CLI-интерфейса — уведомить перед тем, как
продолжить.

## Архитектурные решения

Задача допускает несколько подходов — проверить существующие паттерны проекта и следовать им, если
паттерн очевиден. Паттерн не ясен — представить варианты с компромиссами, рекомендовать с
обоснованием и продолжить. Никаких сигналов — применить лучшие практики и дефолты проекта.

Никогда не выбирать подход молча, когда есть альтернативы.
